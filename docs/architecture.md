# Architecture

```
 Webview (sandboxed, src/webview/)        Extension host (Node, src/extension/)
 ┌──────────────────────────────┐  msg   ┌───────────────────────────────────────┐
 │ dashboard.js + Cytoscape     │ ─────▶ │ messages.ts  validate (opaque ids)    │
 │ renders state, sends ids     │        │ dashboard.ts panel, CSP, open/diff    │
 │ no file/Git/shell access     │ ◀───── │ state.ts     collect + describe       │
 └──────────────────────────────┘ state  └──────┬──────────────────┬─────────────┘
                                                │                  │
                                   src/git/gitChanges.ts   src/analysis/graph.ts
                                   (built-in vscode.git    (TypeScript parser,
                                    extension API)          relative-import resolver)
```

## Key decisions

- **Activation:** happens only when a command runs (`activationEvents: []`), so the extension adds no VS Code startup cost.
- **Git:** uses the built-in `vscode.git` extension API, a minimal typed subset in `gitChanges.ts`. We never run git commands ourselves. Changes are filtered to the selected workspace folder, so separate folders are never mixed. History (Phase 3) uses the same API: `log` for commits, `diffBetween(parent, commit)` for the files of a commit, and `toGitUri` for read-only before/after content; `src/extension/history.ts` issues the opaque `k…`/`h…` ids.
- **Notes (Phase 4):** the only write path. `src/extension/notes.ts` lists `.vibecode/notes/*.md` and creates new note files there, after the owner's per-folder consent, which is kept in `workspaceState`. `src/analysis/notes.ts` holds the pure header reader and file-name rules. The note writer is exported to tests only in `ExtensionMode.Test`.
- **AI sessions (Phase 4b):** the only read outside the project. `src/extension/agentSessions.ts` locates the open project's Claude Code log folder, checks the owner's per-folder permission (`workspaceState`), and streams each `.jsonl` file line by line. `src/analysis/agentLogs.ts` is the pure summariser. It keeps prompts (including messages queued while the agent works), reply text for keyword-based security mentions, token usage counted once per reply id, and edited file paths, and it drops tool results, reasoning and lines from other folders. Summaries are cached by file modification time. Sessions use opaque `a…` ids.
- **Learning aids (Phase 5):** `src/analysis/explain.ts` (pure: roles, iterative Tarjan cycle finder, sentence builders, tips, hover parsing) and `src/analysis/glossary.ts`. `src/extension/explain.ts` gathers the facts: graph edges, symbol kinds, line count, `repo.log({ path })` for commit counts, `vscode.executeHoverProvider` for declarations. `collectState` adds `cycleNodes`, `cycleEdges` and the glossary to the state. Explanations are posted after Details (`explain`, `symbolExplain`), so Details appears without waiting for them.
- **Languages (Phase 6):** `src/analysis/languages.ts` lists the `LanguageSupport` entries (extensions plus `analyze(relPath, text, files)`), and `buildGraph` picks one per file. JS/TS uses the TypeScript parser (`imports.ts`). Python uses `python.ts`: a scanner that removes comments and strings and joins continued lines, then reads `import`/`from` statements and resolves them against the folder's files. Adding a language means adding one entry.
- **Views (Phase 6b):** the dashboard logic is `DashboardSession` (`session.ts`), one per open view. `Dashboard` (`dashboard.ts`) is the VS Code panel. `BrowserView` (`browserView.ts`) is a Node `http` server on 127.0.0.1 that gives each browser tab its own session, sending messages over Server-Sent Events and receiving them by POST. `browserGuard.ts` (pure) checks key, Host, Origin, `Sec-Fetch-Site`, method, content type and asset names. `page.ts` builds the page for both views. `open.ts` holds the editor-opening helpers, so `session.ts` and `dashboard.ts` don't import each other.
- **Code in the browser (Phase 6c):** a browser tab's session is created with `codeInPage`, so clicks on files, commit files, symbols and usages send a `code` message instead of opening VS Code's editor. `codeView.ts` reads the file (`workspace.fs`) or its older version (VS Code Git's `git:` URIs) and refuses sensitive files. `src/analysis/codeText.ts` (pure) splits text into lines, recognises binary files, caps size, and compares two versions with Myers' algorithm, folding unchanged lines. `openInEditor` opens the same item in VS Code. `extension.ts` activates after startup (`onStartupFinished`) for the opt-in `openBrowserOnStartup` setting, and `imports.ts` loads the TypeScript parser on first use so that this stays light.
- **Files tab (Phase 6d):** `files.ts` lists the folder with `workspace.findFiles` (names only, `TREE_EXCLUDE_GLOB`, at most 5,000 files). It reuses graph (`f…`) and change (`c…`) ids and issues `p…` ids for the other files, which the session adds to its targets. `src/analysis/fileTree.ts` (pure) builds the sorted tree with file counts. The webview builds a folder's children when it is first opened.
- **APIs (Phase 7):** `src/extension/apis.ts` reads the graph's source files and the folder's `.sql` / `.prisma` files, then runs pure readers: `apiJs.ts` (TypeScript AST: routes, mounts, `fetch`/`axios` calls, ORM models, Prisma client uses, Next.js exports), `apiPy.ts` (the Python logical-line scanner, which now also reports line numbers), and `apiSchema.ts` (SQL and Prisma). `apis.ts` (pure) applies mount prefixes across files, adds Next.js file routes, matches calls to routes and lists each model's users. Items get `w…` / `x…` / `m…` ids that map to code locations; each carries the graph ids of its files.
- **Pages (Phase 8):** `src/analysis/pages.ts` (pure) builds pages from Next.js file paths (only when a `package.json` lists `next`), React/Vue Router facts from `apiJs.ts`, HTML files and their assets, and routes whose handler renders a template (`RouteView`, from `apiJs.ts` and `apiPy.ts`; Django views via `ViewFact`). `src/extension/apis.ts` adds file names, `package.json` and HTML contents, and graph imports. `previewPage` joins the owner's address to the checked preview URL (`previewAddress`). In VS Code it opens the Simple Browser beside the code. In the browser view it sends `code` and then `pagePreview`, and the page shows a sandboxed frame next to the code. `browserGuard.ts` puts only that origin in `frame-src`.
- **Health (Phase 9):** `src/extension/health.ts` gathers VS Code's diagnostics, file names, three root config files, Git ignore status and tags (`gitChanges.ts`: `getTags`, `ignoredByGit`), AI session start times (only if allowed) and safe-point notes. Pure helpers: `src/analysis/health.ts` (plain problem texts, checklist, possibly unused, near-duplicates, safe points and go-back steps) and `src/analysis/secrets.ts` (credential patterns, now shared with the AI sessions reader, and `findSecrets`, which returns lines only). Locations get `y…` ids; secret locations open only in the editor. **Mark as safe point** writes a note with `safe: true` through the existing notes code.
- **Import parsing:** `typescript` (Apache-2.0) `createSourceFile` gives a syntax-only AST that handles TS, TSX, JS and JSX. It finds `import`, `export … from`, `require`, `import x = require` and `import()`. A non-literal `import()` or `require()` counts as *unknown*.
- **Resolution:** only relative specifiers resolve, trying extensions, `index.*` files and `.js` → `.ts`. Anything that can't be proven (aliases, absolute paths, paths outside the folder) becomes an *unknown* node, and no edge is guessed.
- **Graph rendering:** Cytoscape.js (MIT, zero dependencies), loaded from the local `node_modules` with the built-in `cose` layout. There's no bundler: the webview is plain JS.
- **Symbols:** come from `vscode.executeDocumentSymbolProvider`, so whichever language extensions are installed provide them.
- **Usages (Phase 2):** `vscode.executeReferenceProvider` runs on the clicked symbol's name position, and only when the user clicks. `analysis/usages.ts` (pure) drops locations outside the folder, excluded or sensitive, then de-duplicates them and caps them at 100. Symbols get `s…` ids and usages get `r…` ids. These are valid only for the current Details panel and last lookup, and a refresh clears them. No new dependency: any language with VS Code reference support works.
- **Preview:** `simpleBrowser.show`, falling back to `env.openExternal`. URLs are limited to http/https on loopback hosts.
- **Security boundary:** the webview gets opaque ids such as `f3` and `c1` and never sees file paths for access. The host rejects any id it didn't issue in the current state. The CSP is `default-src 'none'`, with nonce-only scripts and styles from the extension origin. Cytoscape's runtime `<style>` injection is avoided by giving our stylesheet the id it checks for.
- **Limits:** at most `maxGraphFiles` files (default 500, capped at 5000), at most 512 KB per file and 200 symbols per file. Excluded directories and sensitive names are filtered before any read.

## Extending later

Add another language by writing a parser and resolver next to `imports.ts` and choosing one per file extension in `graph.ts`. No plugin framework is needed until a second language exists.
